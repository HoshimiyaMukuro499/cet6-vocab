## 日常怎么用

只有两个操作，都在这个文件夹里：

| 想做什么 | 双击 |
|---|---|
| 编辑单词本 | `编辑文档.bat` |
| 改完了，发布到手机 | `推送更新.bat` |

`推送更新.bat` 会自动做三件事：用 Word 把文档导出成 PDF → 提交改动 → 推送到 GitHub。
推送成功后约 30 秒，手机上刷新就是最新版。

**手机上**：浏览器打开上面的网址，建议「添加到主屏幕」，之后像 App 一样一点即开。
顶部有「下载 PDF」和「下载 Word」两个按钮，下载到本地后断网也能看。
读完往下滑，有一个可以留表情的「表情墙」，见下。

## 文件说明

```
public\               ← 网站发布目录，只有这里的内容会被公开到网上
  单词本.docx          ← 你编辑的文档（用「编辑文档.bat」打开）
  单词本.pdf           ← 自动导出，不要手动改
  index.html          ← 阅读页 + 表情墙
  _headers            ← 缓存策略
  vendor\             ← pdf.js（第三方库，本地托管，见下）
src\
  worker.js           ← 表情墙的服务端接口（线上唯一的动态部分）
migrations\
  0001_init.sql       ← 表情墙的数据库表结构（权威版本）
tools\
  export-pdf.ps1      ← 调用 Word 导出 PDF 的脚本
  test-api.mjs        ← 接口的自动化测试（见下）
wrangler.jsonc        ← Cloudflare 部署配置
package.json          ← 只为钉住 wrangler 版本，站点本身没有运行期依赖
编辑文档.bat
推送更新.bat
```

⚠️ **`src\` 里是服务端代码，绝不能挪进 `public\`**——那个目录下的所有东西
都会公开发布，等于把管理逻辑连同删除接口一起交出去。

**关于 `vendor\`**：手机的浏览器不会内嵌显示 PDF，所以阅读页用 pdf.js
把每一页画到 canvas 上，再按屏幕宽度缩放。这个库是**打包在站点里**的，
不从境外 CDN 加载，站点运行时零外部依赖。

⚠️ 里面用的是 pdfjs-dist 的 **legacy** 构建，**不要**换成常规构建。
常规构建依赖 `Uint8Array.prototype.toHex` 等很新的 JS 特性（Chrome 140+），
手机上较旧的浏览器会直接报 `toHex is not a function` 而白屏。

## 表情墙

读完文档往下滑，有一个方形区域和排表情按钮。访客点一个，就留在墙上，
**所有访客看到的是同一面墙**，5 秒内自动同步。

**每次浏览可以留一个**。刷新页面算一次新的浏览，所以想再留一个，刷新即可。

### 站主删除

在网址后面加上 `#admin=你的管理令牌` 再打开，就会进入管理员模式：

```
https://cet6-vocab.749316609.workers.dev/#admin=你的管理令牌
```

进入后，**点任意表情即可删除**，底部会多出一个「清空表情墙」按钮。
令牌在打开页面时就会从地址栏里被抹掉（避免截图或分享时泄露）。

令牌错误或没带令牌时，页面**完全不显示**任何管理入口，墙照常可用。

管理令牌存放在 Cloudflare 后台的变量里，**不在这个仓库里**。忘了就去
Cloudflare → 你的 Worker → `Settings` → `Variables and Secrets` 里重置。

### 第一次启用（只需做一次）

代码已经写好了，但**线上还没有数据库**，所以现在推上去，表情墙那一块会显示
「表情墙正在准备中，稍后再来」。**PDF 和两个下载按钮完全不受影响**——
这是有意为之：数据库没配好不该连累阅读。

按下面四步做一次，之后永久有效：

**第 1 步：建数据库、建表**

Cloudflare 后台 → 左侧 `Storage & Databases` → `D1 SQL Database` → `Create`。
名字填 `cet6-emoji`，确定。

进去之后做两件事，都在这个页面上：

1. 复制 **Database ID**（形如 `a1b2c3d4-...` 的一长串），等一下要用
2. 切到 `Console` 标签，用记事本打开本文件夹的 `migrations\0001_init.sql`，
   **把整个文件的内容复制粘进去**，执行一次

（第 2 件事不做也能用——Worker 检测到表不存在会自己建。但那样每次部署后的
第一个请求都会慢一点，日志里也会刷警告。手动建一次更干净。）

**第 2 步：把 Database ID 填进 `wrangler.jsonc`**

用记事本打开本文件夹里的 `wrangler.jsonc`，找到这一行：

```jsonc
"database_id": "00000000-0000-0000-0000-000000000000"
```

把引号里那一串 `0` **整个替换成**你刚复制的 ID，保存。

**第 3 步：设管理令牌**

Cloudflare 后台 → 你的 Worker（`cet6-vocab`）→ `Settings` →
`Variables and Secrets` → `Add`。

- 类型选 **Secret**（不是 Text）
- 名字填 `ADMIN_TOKEN`（一字不差）
- 值填一段**长一点的随机字符串**，自己随便敲，比如三四十个字符

保存。**这串东西就是你删除表情用的令牌，记住它**（存到手机备忘录里）。
它不会出现在网页上，也不在 GitHub 仓库里。

**第 4 步：推送验收**

双击 `推送更新.bat`，等 Cloudflare 部署完（约 1 分钟），打开网站往下滑，
方块和表情按钮应该出来了。留一个表情试试，然后换台设备打开——应该能看到。

做完这四步，所有设备看到的就是同一面墙了。

### 以后想改表情墙

改完 `src\worker.js` 或 `public\index.html` 照旧双击 `推送更新.bat` 即可，
数据库不用再动。

## 出问题怎么办

**PDF 导出失败，但 Word 文档推送成功了？**
最常见的原因是 Word 里开着弹窗对话框（比如"是否保存"），自动化调用会卡在上面。
把 Word 里的对话框点掉，再双击一次 `推送更新.bat`。

**连点两次推送，第二次报"无法启动 Word"？**
Word 关闭是异步的，进程要十几秒才真正退出。脚本已内置重试，等十几秒再试即可。

**手机上打不开网址？**
`workers.dev` 在中国大陆没有节点，走跨境线路，部分运营商（尤其移动）可能连不上。
先试试换 WiFi / 换流量。如果长期不行，见下面「换域名」。

**首页顶部显示「无法读取版本时间」？**
更新时间是读 PDF 的 `Last-Modified` 响应头得到的。读不到不影响阅读和下载，
只是少了个时间戳。下拉刷新通常即可恢复。

**手机上还是旧内容？**
先下拉刷新。页面已设置不使用缓存，正常情况下刷新即可拿到最新版。

**表情墙显示「正在准备中」或「暂未开启」？**

- **「表情墙正在准备中，稍后再来」**：Worker 连不上数据库。多半是数据库还没建，
  或者 `wrangler.jsonc` 里的 Database ID 没填对。回到「第一次启用」的四步。
  **建好之后不用刷新页面，它自己会在半分钟内接上。**

- **「表情墙暂未开启」**：接口整体不存在——通常是还没部署上去。

两种都只影响表情墙，**PDF 和两个下载按钮完全不受影响**。

**留表情时提示「稍后再试」？**
多半是短时间留的人太多，撞到了防刷上限（全站每分钟 60 个）。等一分钟再点。
真人几乎碰不到这个数。

**删表情时提示「令牌无效」？**
`ADMIN_TOKEN` 没设，或者网址里带的令牌和后台那串不一致（小心首尾空格）。
令牌只在打开页面时读一次，改过之后要**重新打开带 `#admin=` 的网址**。

**推送成功，但网站行为没变？**
检查 `wrangler.jsonc` 里的 `name` 是不是 `cet6-vocab`。写错会**静默新建一个
Worker**，部署到另一个网址，而原来那个网址纹丝不动。

## 换域名（如果 workers.dev 长期打不开，或想在电脑上也打开）

`workers.dev` 的失效主要是**域名级封锁**（这个域名本身就是目标），换成自己的域名可以绕开。
花 ¥10–30/年 买个 `.top`/`.xyz`，在 Cloudflare 的 Worker 项目里
`Settings` → `Domains & Routes` → `Add` → `Custom Domain`，按提示改 DNS 即可。
需要实名，但**不需要备案**。

换完记得**回来改本文件顶部和 `public/index.html` 里没有写死域名的部分**
（阅读页用的是相对路径，不用改；只有本文件顶部那一行网址要更新）。

注意：跨境线路的延迟（约 150–300ms）换域名也解决不了，只能缓解"打不开"。

网上流传的 Cloudflare「优选 IP」不要用——违反服务条款，可能直接封号。

## Cloudflare 配置备忘

线上是 **Worker + Static Assets**。加了表情墙之后，这个项目**不再是纯静态**：
仓库里多了一段服务端代码（`src\worker.js`）和一份数据库（D1）。

- Git 仓库：`HoshimiyaMukuro499/cet6-vocab`，分支 `main`
- 部署命令：`npx wrangler deploy`（会自己读 `wrangler.jsonc`）
- Build command: **留空**
- Build output directory: **留空** ← 纯静态时代的遗留项，见下

**`推送更新.bat` 不用改。** 它照旧只负责提交和推送，Cloudflare 收到后执行
`wrangler deploy`。用户的操作没有增加任何一步。

⚠️ 「Build output directory: `public`」是纯静态时代的设置。现在输出目录由
`wrangler.jsonc` 的 `assets.directory` 决定，这一项应当**清空**；留着它通常
只是被忽略，但如果部署报错，第一个要怀疑的就是这里。

⚠️ **`wrangler.jsonc` 里的 `name` 必须和后台的 Worker 名字完全一致**
（`cet6-vocab`）。写错不会报错，而会**静默新建一个 Worker** 部署到别的网址，
表现是「推送成功了但网址没变化」。

## 本地预览与测试

线上的东西改动前，先在本机跑一遍。**不需要登录 Cloudflare，也不碰线上数据**
——`wrangler dev` 用本地的 SQLite 模拟 D1。

```bash
npm install                          # 只需一次
echo 'ADMIN_TOKEN=本地随便写一个' > .dev.vars   # 只需一次，会被 .gitignore 挡下
npx wrangler dev --port 8787         # 起本地服务，然后浏览器开 http://127.0.0.1:8787
```

⚠️ **改过 `.dev.vars` 之后必须重启 `wrangler dev`。** 它只在启动时读一次，
之后一直用内存里那份。不重启的话，测试会报「令牌对不上」，而你会去查
鉴权代码——那里其实是对的。

另开一个终端跑接口测试（77 条断言，覆盖增删改查、幂等、鉴权、并发、防刷、
以及静态资源回归——加 Worker 最容易悄悄弄坏的就是静态那部分）：

```bash
node tools/test-api.mjs        # 它会自己从 .dev.vars 里读 ADMIN_TOKEN
```

⚠️ **本地测试跑完会清空本地数据库**，这是有意的：本地 D1 是持久化的，上次
留下的行会让「空库」这类前提失效，失败项看着像代码坏了，其实只是测试不幂等。
**这只影响本地，线上数据不受任何影响**（脚本只打 `127.0.0.1`）。

⚠️ 想确认没有残留的旧实例占着端口：

```bash
netstat -ano | grep :8787 | grep LISTENING
```

重复启动的 wrangler 会**静默堆在同一个端口上**，此时请求会随机打到旧实例，
于是「明明改了代码却没生效」或「令牌明明是对的却报无效」——这两类怪事我都
真的踩到过。

⚠️ 在 git-bash 里 `pkill -f wrangler` **杀不掉**原生 Windows 进程，进程会
继续活着。用：

```bash
taskkill //F //IM workerd.exe
```
